# Інформаційна система технічних заявок готельного комплексу

Курсова робота з дисципліни «Кросплатформене програмування», варіант №13.
Студент: Колесник Максим Іванович, група 203-ТН.

Клієнт–серверна система: **JavaFX-клієнт → HTTP/JSON → Servlet → Service → DAO → JDBC → MySQL**.
Система обліковує номери готелю, заявки про несправності, фахівців технічної служби та записи виконання.
Заявка проходить чотири стани: `NEW → ASSIGNED → IN_PROGRESS → DONE`. Для кожної заявки сервер
обчислює інтегральний показник пріоритету `I = 0,40·F1 + 0,35·F2 + 0,25·F3` (F1 – вплив на гостя,
F2 – тяжкість несправності, F3 – вплив на доступність номера; усі значення 0–100).

## Технології

- Java 21, Maven
- JavaFX 21.0.2 (клієнт), Jackson Databind 2.18.2
- Servlet API 4.0.1 (`javax.servlet`), Apache Tomcat 9.x
- MySQL (XAMPP), MySQL Connector/J 9.7.0
- JUnit 5.11.4

## Підготовка MySQL

1. Запустіть Apache і MySQL у XAMPP Control Panel.
2. Відкрийте `http://localhost/phpmyadmin`, перейдіть на вкладку **Імпорт**, виберіть файл `database.sql` і виконайте його.
3. Буде створено базу `hotel_service`. Повторне виконання файла відтворює базу з нуля.
Параметри підключення (`localhost:3306`, користувач `root`, порожній пароль) задано в класі `DBUtil`.

## Складання й запуск сервера

```
cd server
mvn clean package
```

1. У каталозі `server/target` буде створено `hotel-requests-server.war`.
2. Зупиніть Tomcat 9.x, видаліть зі `webapps` старий WAR і однойменну папку.
3. Скопіюйте новий WAR у `webapps` і запустіть Tomcat.
4. Перевірте: `http://localhost:8080/hotel-requests-server/rooms` повертає JSON зі списком номерів.

Маршрути: `/rooms`, `/specialists`, `/requests`, `/records`. Читання – `GET`; додавання,
редагування, видалення та зміна стану – `POST` із параметром `action`.

## Запуск JavaFX-клієнта

Tomcat і MySQL мають бути запущені.

```
cd client
mvn javafx:run
```

Каталог `client` має бути поточним: файл CSV підключається за відносним шляхом `sample-data/rooms.csv`.

## Тести

```
cd server
mvn clean test
```

Модульні тести (JUnit 5) перевіряють розрахунок інтегрального показника, правила переходів
життєвого циклу та валідацію. Для них не потрібні MySQL, Tomcat і JavaFX.

## CSV-файл і фоновий імпорт

Файл `client/sample-data/rooms.csv`, кодування UTF-8, роздільник `;`, перший рядок – заголовок:

```
room_number;floor;room_type;capacity;equipment
102;1;Стандарт;2;Кондиціонер, телевізор, сейф
```
Усі п’ять полів обов’язкові; `floor` і `capacity` – цілі числа. Для імпорту відкрийте вкладку
**Номери** та натисніть **Імпортувати CSV**: імпорт виконується у фоні (JavaFX `Task`), хід
відображає `ProgressBar`, а записи передаються серверу через HTTP. Рядки з неправильним форматом
пропускаються з попередженням у журналі; помилки файла чи сервера зупиняють імпорт. Номери, які вже
є в базі або повторюються у файлі, пропускаються як дублікати (лічильник «дублікатів»), тому повторний
запуск імпорту нічого не задвоює.

## Захист від дублікатів

Перевірка виконується на сервері (Service → DAO) без урахування регістру й зайвих пробілів, а для
номера кімнати й телефону додатково діють UNIQUE-обмеження в БД. Помилка повертається як HTTP 400.

| Сутність | Що вважається дублікатом |
|---|---|
| Номер | той самий `room_number` |
| Фахівець | той самий телефон (порівняння за цифрами) або та сама пара «ПІБ + спеціалізація» |
| Заявка | для того ж номера вже є незавершена заявка (не `DONE`) з таким самим описом |
| Запис виконання | та сама заявка, фахівець, дата й опис робіт |
